# Release runbook: CricHeroes-parity migrations 0038–0047

All ten migrations are idempotent (safe to re-run) and additive: they add columns, tables, functions, triggers and policies, and drop no data. Run them **in number order**.

## Step 1: run the SQL

You can do this either of two ways:

- **One paste:** run [`2026-10-parity-0038-0047.sql`](2026-10-parity-0038-0047.sql) in Supabase → SQL editor. It contains the ten blocks, each in its own transaction.
- **One at a time:** run each file in the table below.

| # | File | Feature | What it changes |
|---|---|---|---|
| 0038 | [2026-10-media-storage-0038.sql](2026-10-media-storage-0038.sql) | #01 image uploads | Public `media` storage bucket + per-user write policies |
| 0039 | [2026-10-scoring-lock-0039.sql](2026-10-scoring-lock-0039.sql) | #03 one active scorer | `matches.active_scorer_*`; claim / handover / release / append / pop RPCs; guard + `clear_scoring_lock` triggers |

Quick check after running:

```sql
select column_name, table_name from information_schema.columns
 where (table_name, column_name) in (('matches','active_scorer_id'),('matches','result'),('tournaments','deleted_at'),
   ('teams','admin_ids'),('matches','officials'),('tournaments','awards'),('matches','potm'),('follows','prefs'));

select proname from pg_proc where proname in
  ('join_match_as_scorer','can_admin_player','redeem_tournament_invite','notify_match_status');
```

## Step 2: Vault secrets for 0047 (match start/result alerts)

Until these exist, the 0047 trigger does nothing; it never blocks a status change. Run once in the SQL editor:

```sql
select vault.create_secret('https://mpgbvbylmkwasjgupsbq.supabase.co/functions/v1/notify-followers', 'notify_followers_url');
select vault.create_secret('<the same value as the notify-followers WEBHOOK_SECRET>', 'webhook_secret');
-- only if notify-followers has JWT verification ON (the public anon key, as in 2026-10-schedule-reminders.sql):
select vault.create_secret('<anon key>', 'functions_anon_key');
```

If a secret with that name already exists, use `vault.update_secret(id, new_value)` instead.

## Step 3: deploy edge functions *before* the app update

- **`notify-followers`.** This version carries #05's "push only headline increases" diff, the #23 per-follow choices and the new `match_status` branch. It **must be live before** an OTA or web publish that includes #05 corrections or the #19 completion stat sync. Otherwise those updates would push to every player's followers.
- **`notify-upcoming`.** Skips followers who turned "Before they play" off.

## Step 4: staging checks

1. Score a few balls. The `notify-followers` logs show **no** invocations.
2. Start a match (scheduled → live), then finish it. You should see **one** invocation each.
3. On a phone that follows a team in that match: one "is live" alert and one "Full time" alert.

## Step 5: ship

Publish the web/OTA update, build a new APK, and run `git push --all`.
